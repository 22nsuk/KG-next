# 공유 서비스 제거와 Yike 메시지 검증

## 제거 범위

`lizzieyzy.cn` 전용 공유·일괄 업로드·로그인·공개/개인 기보 검색·공유 정보 편집 기능과 해당 TCP 클라이언트를 제거했습니다. 기능 검색의 공유 내역 항목도 더 이상 표시하지 않습니다. 기존에 동작하지 않던 Ctrl+E와 Alt+B는 다른 명령으로 재할당하지 않습니다.

일반 SGF 열기·저장·내보내기, 로컬 저장 목록, Fox/Tencent/Yike 온라인 기보 기능은 유지합니다. `SMessage`는 판독 보드에서도 사용하므로 유지하며, SGF 직렬화의 기존 형식은 변경하지 않습니다.

## 기존 설정 처리

정상적으로 읽은 주 설정의 `ui`에서 다음 키만 제거합니다.

- `up-load-user`, `up-load-passwd`
- `share-label-1`부터 `share-label-5`
- `share-public`, `share`

정상적으로 읽은 창 상태 파일에서는 `ui-persist.public-kifu-search`만 제거합니다. 일반 화면 비율 설정 등 이름에 `share`가 들어 있는 다른 키는 유지합니다. 제거 결과는 기존 설정 저장기를 통해 같은 디렉터리의 임시 파일에 쓴 뒤 교체합니다. 읽기나 임시 파일 생성·쓰기 실패는 기본값 복구로 처리하지 않고 시작 오류를 전달하므로, 원본을 유지한 채 권한 등을 복구하고 재실행할 수 있습니다.

기존 설정 저장기는 원자적 이동을 먼저 시도하지만, 파일시스템이 이를 지원하지 않으면 일반 교체를 사용합니다. 이 fallback에서 발생하는 장애까지 원자적 교체나 원본 보존을 보장하는 것은 아닙니다. 이번 변경은 기존 저장 정책을 유지합니다.

과거에 사용자가 만든 백업이나 손상 파일의 기존 복구 백업은 일괄 삭제하지 않습니다. 해당 백업에 폐기 서비스 비밀번호가 남아 있을 수 있습니다.

## Yike 메시지 허용 조건

`yikeUnite:`와 `yikeGeometry:`는 아래 조건을 모두 만족해야 처리합니다.

1. Yike 모드로 연 브라우저 창입니다.
2. CEF가 전달한 메시지 발신 프레임이 주 프레임입니다.
3. 그 프레임의 실제 URL이 HTTP 또는 HTTPS이고, 호스트가 `yikeweiqi.com` 또는 점으로 구분된 하위 도메인입니다.

주소창 문자열이나 메시지 본문의 `href`는 출처 증거로 사용하지 않습니다. 다른 도메인, 유사 도메인, 하위 프레임, 프레임 누락, 잘못된 URL과 `data:`·`file:`·오류 페이지 출처는 403으로 거절하며 성공 응답·상태 변경·worker 전달 전에 차단합니다. 일반 메시지의 다른 handler 전달과 정상 Yike 메시지의 비동기 처리는 유지합니다.

이 변경은 업스트림 #631의 출처 검증만 반영합니다. JCEF 버전·네이티브 번들·설치 패키지는 변경하지 않으며, 브라우저 자체의 버전 갱신을 대체하지 않습니다. 기존 Yike 세션 처리는 변경하지 않습니다. 방 전환 전에 수신하여 worker에 대기 중인 응답을 현재 방에 적용할 수 있는지 검증하는 것은 별도 범위이며, 이 출처 검사만으로 이전 방의 모든 지연 응답이 차단된다고 보장하지 않습니다.

## 검증

`ConfigRetiredShareAccountTest`는 실제 설정 파일의 제거·재실행·무관한 값 보존 및 읽기/쓰기 권한 실패 후 복구를 검증합니다. `BrowserFrameYikeQueryOriginTest`는 실제 생산 메시지 handler를 호출하여 두 접두어의 거절·허용·비동기 전달을 확인합니다. CEF 프레임은 제어 가능한 대역으로 제공하므로, 이 검사는 네이티브 Chromium과 실제 Yike 서비스 접속의 수동 검증을 대신하지 않습니다.
