# 웹 시험 모드 명령과 소유권

웹 관전 페이지를 업데이트한 뒤에는 기존 탭을 새로고침해야 합니다. 예전의
`clientId`만 보내는 클라이언트는 시험 국면을 변경할 수 없습니다. 관전은 그대로
가능하며, 같은 `clientId`를 사용하는 다른 탭은 소유자가 아닙니다.

## 연결과 재접속

`enter_trial`은 표시용 `clientId`를 받습니다. 진입에 성공하면 서버는 실제 연결을
소유자로 등록하고 그 연결에만 `trial_granted`를 보냅니다. 응답의 `sessionId`는
세션 구분자이고, `resumeToken`은 비공개 재접속 자격입니다. 공개 `trial_state`에는
`sessionId`와 `ownerClientId`가 포함되지만 토큰은 포함되지 않습니다.

착수·이동·초기화·종료에는 현재 `sessionId`와 `clientId`가 필요하며 실제 연결도
소유자와 일치해야 합니다. 명령 접수와 실행 시 모두 검사합니다. 같은 연결이어도
이전 세션의 명령으로 새 세션을 조작할 수 없습니다.

소유자 연결이 끊기면 같은 탭은 `sessionStorage`에 보관한 자격으로 `resume_trial`을
보냅니다. 서버는 `sessionId`, `clientId`, `resumeToken`을 검사하고 이전 연결이 닫힌
경우에만 연결을 교체합니다. 성공할 때마다 토큰을 교체하며 이전 토큰은 폐기합니다.
이전 연결이 아직 살아 있으면 재접속 요청도 소유권을 빼앗지 못합니다. 5분 유휴 제한,
명시적 종료, 서버 중지 또는 보드 교체 이후에는 새로 진입해야 합니다.

이 기능은 **접속한 클라이언트 사이의 시험 소유권**을 보호합니다. 서버 접속 자체의
사용자 인증이나 TLS를 추가하는 변경은 아닙니다. 기존 HTTP/WS 연결은 평문이므로
신뢰하지 않는 네트워크나 인터넷에 그대로 공개하지 마세요. 토큰을 URL·로그·공개
방송에 넣어서는 안 됩니다.

## 순서와 규칙

모든 네트워크 시험 명령은 기존 collector의 단일 실행기에 한 번만 예약됩니다.
동일 연결의 수신 순서를 유지하며, 착수를 두 번 예약해 이후 초기화가 먼저 실행되는
경로는 없습니다. 데스크톱의 강제 종료는 즉시 세션을 무효화하고 대기 명령은 실행
시 재검증합니다. 공개 상태는 느린 클라이언트별 최신 값으로 병합할 수 있으므로
관전자에게 모든 중간 상태 메시지가 전달되는 것은 아닙니다.

기존 분기 재사용은 좌표뿐 아니라 착수 노드와 색상까지 일치해야 합니다. 새 후보를
검증한 후에만 재사용하고, 일반 보드의 현재 `violatesKoRule`과 같은 **단순 패**
판정 및 `canSuicidal`에 따른 자충 정책을 적용합니다. 실제 보드의 히스토리 커서는
옮기지 않습니다. KataGo의 모든 규칙 조합이나 superko를 새로 구현한 것은 아닙니다.

## 기동과 검증

포트와 연결 수 설정을 자원 생성 전에 검사합니다. HTTP 및 WebSocket의 실제 바인딩과
준비 완료를 확인한 뒤 URL과 실행 상태를 공개합니다. 포트 충돌은 최대 10개의 유효
포트에서 재시도하고, `0`은 운영체제의 임시 포트를 사용합니다. 중간 실패·중지에는
listener와 실행기를 정리하고 상태 잠금 밖에서 서버 스레드 종료를 기다립니다.

Java 회귀 테스트는 기존 Maven CI에서 실행합니다. 별도 의존성 없이 웹 페이지의
실제 JavaScript를 실행하는 프로토콜 검사는 Node 22에서 실행합니다.

```sh
mvn -B -Djava.awt.headless=true '-Dtest=featurecat.lizzie.gui.web.*Test' test
node --test scripts/test_web_trial_protocol.mjs
```

소켓 검사는 loopback의 실제 연결을 사용하고, JavaScript 검사는 DOM과 소켓만
시험 객체로 대체합니다. 실제 브라우저의 시각적 표시나 사용자 PC의 KataGo GPU
실행을 대신하는 검사는 아닙니다.
