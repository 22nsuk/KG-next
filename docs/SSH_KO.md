# SSH 연결과 비밀번호

일반 엔진, 독립 분석 엔진, 기여 모드와 원격 서버 목록 조회는 같은 SSH 연결 경계를 사용합니다. 비밀번호 인증과 암호화되지 않은 개인 키 파일을 지원하며, 두 방식 모두 설정한 포트로 연결합니다. 개인 키의 암호 입력, SSH agent, 사용자 홈의 SSH 설정·키 자동 선택은 제공하지 않습니다.

## 서버 키 확인

서버 키는 작업 폴더의 `ssh/known_hosts`에 OpenSSH 형식으로 기록합니다. 기본 포트는 호스트 이름, 다른 포트는 `[호스트]:포트`로 구분합니다. 같은 작업 폴더를 사용하는 연결끼리는 키 확인과 첫 기록을 잠금으로 직렬화합니다.

- 처음 연결하는 서버는 받은 키를 파일에 성공적으로 기록한 뒤에만 인증을 진행합니다. 파일을 읽거나 기록할 수 없으면 연결을 거부합니다.
- 이후 연결에서는 기록된 키와 대조합니다. 키가 다르면 비밀번호 인증이나 원격 명령 실행 전에 연결을 거부하며, 기존 키를 자동으로 교체하지 않습니다.
- 키 변경 오류에는 기존·새 키의 지문과 확인할 파일 경로를 표시합니다. 잘못된 파일 내용과 자동 처리하지 않는 marker가 있는 항목도 수동 확인이 필요합니다.

이 방식은 **최초 연결 때 받은 키를 신뢰하는 TOFU**입니다. 최초 서버의 신원을 별도 경로로 증명하지는 않습니다. 처음부터 검증된 서버만 사용해야 하는 환경에서는 관리자에게 신뢰할 수 있는 경로로 확인한 호스트 공개 키를 받아 연결 전에 해당 항목을 준비하세요. 단순히 네트워크에서 수집한 키만으로 신원을 확인했다고 판단하지 마세요.

서버를 재설치하거나 키를 교체했다면 먼저 관리자에게 변경 사실과 새 지문을 확인하세요. KG-next를 종료하고 `known_hosts`를 백업한 뒤 해당 호스트·포트 항목만 검증된 키로 수정합니다. 오류를 없애기 위해 파일 전체를 지우거나 확인되지 않은 새 키를 그대로 신뢰하지 마세요. 작업 폴더를 옮길 때 이 파일도 함께 보관해야 기존 서버 키 기록이 이어집니다.

기존 서버와의 호환을 위해 SHA-1 기반 일부 키 교환 방식은 낮은 우선순위로 남아 있습니다. 서버에서 현대적인 방식도 제공하면 클라이언트의 기본 우선순위를 먼저 사용합니다. 이 변경이 모든 레거시 알고리즘을 제거했다는 뜻은 아닙니다.

## 비밀번호 저장과 설정 취소

사용할 수 있는 OS 보안 저장소를 우선 사용합니다. Windows는 DPAPI, macOS는 Keychain, Linux는 Secret Service의 `secret-tool` 경로를 사용합니다. 정상적으로 기록하고 다시 읽어 확인한 비밀번호는 `config.txt`에 비밀번호 대신 `passwordRef`로 연결합니다. 기존 저장 형식은 앱 시작 시 동일한 설정 저장 절차를 통해 옮깁니다.

설정 창에서 비밀번호를 입력하거나 하위 원격 설정 창을 확인하는 것만으로 기존 보안 저장소 값을 바꾸지는 않습니다. 상위 설정의 실제 저장 시 새 항목을 만들고, 설정 파일 저장이 성공한 뒤에만 그 참조를 사용합니다. 설정 파일 저장 실패 시 이번 시도에서 만든 항목만 정리하며 기존 설정과 비밀번호를 유지합니다. 이전 참조는 다른 설정이나 백업이 사용할 수 있으므로 자동 삭제하지 않습니다.

**보안 저장소를 사용할 수 없거나 저장·읽기 확인에 실패하면 기존의 가역적인 난독화 저장 방식을 유지합니다. 이것은 강한 암호화가 아닙니다.** 비밀번호 입력란의 안내에도 이 조건을 표시합니다. 이 환경에서는 설정 파일과 백업을 비밀번호가 포함될 수 있는 파일로 취급하세요. 개인 키 인증을 사용할 수도 있습니다.

이미 저장된 `passwordRef`를 읽을 수 없을 때는 빈 비밀번호로 덮어쓰지 않습니다. 설정 창에서 그 입력란을 그대로 두면 기존 참조를 보존하고, 새 비밀번호를 입력하면 교체 후보로 처리합니다. 실제 연결 시 비밀번호를 읽을 수 없으면 연결 오류를 안내합니다.

보안 저장소의 항목은 OS 계정이나 컴퓨터에 종속될 수 있습니다. 다른 컴퓨터로 무설치 패키지를 복사했다고 해서 비밀번호도 자동으로 복구되는 것은 아닙니다. 새 환경에서 비밀번호를 다시 입력하거나 원래 보안 저장소에 접근할 수 있게 해야 합니다. 새 형식의 설정을 이전 버전 앱으로 되돌릴 때도 `passwordRef` 지원 여부를 확인하고, 필요하면 변경 전 설정 백업을 사용하세요.

## 연결 종료와 검증 범위

연결을 시작하는 동안 엔진이 중지되면 진행 중인 연결도 종료 대상이 됩니다. 늦게 연결이 완료돼도 폐기된 엔진의 세션이나 오류를 다시 표시하지 않습니다. 기여 모드는 해당 연결의 입력으로 `forcequit`를 보낸 뒤 닫아 원격 작업자 종료 동작을 유지합니다. 이전 연결을 닫는 작업이 후속 연결을 종료해서는 안 됩니다.

회귀 검사는 로컬 SSH 서버를 사용해 인증, 서버 키 변경·기록 실패, 연결 취소, 명령 입출력과 기여 모드 종료를 확인합니다. 자격증명 저장은 설정 취소, 파일 저장 실패, 보안 저장소 실패, 기존 참조 보존을 별도로 검사합니다. 실제 운영 서버의 설정, macOS/Linux 데스크톱 보안 저장소 접근 권한, 사용자 컴퓨터의 개인 키 형식과 최종 배포 패키지는 해당 환경에서 확인해야 합니다. 검사 실행 방법은 [개발 문서](DEVELOPMENT.md)를 참고하세요.
