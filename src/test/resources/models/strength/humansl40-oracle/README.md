# HumanSL40 synthetic inference oracle

`predictions.json` contains expected predictions generated by the official
XGBoost **3.2.0** CPU implementation, independently of the Java scorer. JUnit
uses the checked-in data without Python, network access, or a local KataGo engine.
The fixture also pins the bundled booster SHA-256 and its exact feature order.

The 25 vectors cover ordinary synthetic values, zeros and ones, missing values
(`null` means `Double.NaN`), and two root split thresholds with different float32
rounding directions. Threshold cases include the neighboring float32 values and
float64 values immediately around the JSON and float32 thresholds. They detect a
direct double comparison that chooses a different branch from XGBoost's float32
input and threshold semantics. All missing-value defaults in this particular
booster point right; the fixture tests that model's actual routing.

Expected values come from `Booster.predict` with a dense float64 `DMatrix`,
`missing=np.nan`, `device=cpu`, and one thread. The fixture retains the raw
prediction and the product's rank clamp to `[0, 12]`; these cases all fall inside
that interval. `expected_leaf` records the official result for the selected tree
as diagnostic evidence. The test compares the complete ensemble prediction.
The absolute tolerance of `2e-5` allows small floating-point accumulation
differences; it is not a strength-estimation confidence interval.

These are synthetic feature vectors, not extracted game records. They verify
model loading, feature order, missing-value routing, and prediction arithmetic.
They do **not** validate feature extraction from games, training-data quality,
rank calibration, or actual playing-strength accuracy. No private parity
fixture or training game was used.

## Reproduce

From the repository root, create a separate environment and regenerate the
fixture with the pinned model. The script rejects a different model hash or
XGBoost version.

```bash
python3 -m venv /tmp/humansl40-oracle
/tmp/humansl40-oracle/bin/python -m pip install \
  'xgboost-cpu==3.2.0' 'numpy==2.3.5' 'scipy==1.17.0'
/tmp/humansl40-oracle/bin/python \
  src/test/resources/models/strength/humansl40-oracle/generate.py \
  --model src/main/resources/models/strength/humansl40_booster.json \
  --output src/test/resources/models/strength/humansl40-oracle/predictions.json
git diff -- src/test/resources/models/strength/humansl40-oracle/predictions.json
```

Generation was verified on Linux x86_64 with Python 3.12.14, NumPy 2.3.5,
SciPy 1.17.0, and the official `xgboost-cpu` 3.2.0 wheel. The XGBoost project
documents its [CPU-only package](https://xgboost.readthedocs.io/en/stable/install.html#minimal-installation-cpu-only).

[PyPI release metadata](https://pypi.org/pypi/xgboost-cpu/3.2.0/json):
